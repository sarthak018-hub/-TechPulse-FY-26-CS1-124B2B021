## 1. Project Overview

The **AUTOSAR HLD Document Analysis Assistant** is an offline, AI-assisted engineering tool designed to streamline technical reviews of automotive High-Level Design (HLD) specifications. Modern vehicle electronic control units (ECUs)—such as the Body Control Module (BCM)—depend on lengthy, semi-structured architectural documents defining software components, port interfaces, signals, and functional sequences.

### Core Objectives
1. **Accelerate Architectural Reviews:** Reduce manual engineering review time through grounded semantic search.
2. **Traceability of Components & Signals:** Deterministically extract and catalog software components (SWCs), Sender-Receiver (S/R) interfaces, Client-Server (C/S) interfaces, and CAN-FD/LIN signals.
3. **Automated Revision Comparison:** Reliably detect breaking interface changes, renamed signals, removed ports, data type mismatches, and orphan interfaces between architectural revisions (v1.0 baseline vs v2.0 revision).
4. **Zero-Hallucination & Offline Privacy:** Enforce strict citation requirements (`[doc_id, version, page, section]`) and dual-stage refusal gates without sending any intellectual property to external cloud APIs.

> **Advisory Notice:** All outputs generated by this system are advisory and require review and sign-off by a qualified automotive systems architect.

## 3. Prerequisites & Environment Setup

### Hardware Specifications
- **Operating System:** Windows 10/11 or Linux
- **RAM:** 12 GB RAM minimum
- **VRAM / GPU:** CPU execution supported; optional NVIDIA GPU with 2 GB+ VRAM
- **Storage:** ~3 GB free disk space (models + dependencies)

### Step 1: Clone / Navigate to Directory
```bash
cd PCCOE_Sarthak_PRN_CS1_AIML
```

### Step 2: Create Python Virtual Environment (Python 3.11)
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### Step 3: Install Pinned Dependencies
```powershell
pip install -r Code\requirements.txt
```

### Step 4: Download Local Large Language Model (Ollama)
Ensure the Ollama service is installed and running locally, then pull the target quantized model:
```bash
ollama pull qwen2.5:3b
```
*(Optional for 16 GB+ workstations: `ollama pull qwen2.5:7b`)*

## 4. Execution Workflow

### Step 1: Generate Synthetic Test Datasets
Generates the 14-page baseline `HLD_BodyControl_v1.pdf`, the 14-page revised `HLD_BodyControl_v2.pdf` (with 6 seeded defects), and ground-truth metadata:
```powershell
python Code\generate_synthetic_data.py
```

### Step 2: Ingest & Embed Specifications
Parses documents with PyMuPDF/pdfplumber, creates section-aware chunks with preserved Markdown tables, generates `BAAI/bge-small-en-v1.5` dense embeddings, and stores them in ChromaDB:
```powershell
python Code\ingest.py
```

### Step 3: Extract Architectural Entities
Extracts SWCs, interfaces, signals, and port bindings into JSON and CSV catalogs:
```powershell
python Code\extract_entities.py
```

### Step 4: Run Architectural Revision Comparison
Executes the deterministic 5-rule comparison engine to detect all discrepancies between v1.0 and v2.0:
```powershell
python Code\compare.py
```

### Step 5: Launch Streamlit Web User Interface
Starts the interactive browser application featuring 6 tabs (Q&A Assistant, Ingestion, Entity Explorer, Revision Compare, Export Center, Compliance Audit Log):
```powershell
streamlit run Code\app.py
```
Open your browser at: `http://localhost:8501`

### Step 6: Execute Benchmark Evaluation Suite
Runs the 20-question quantitative benchmark measuring Hit@k, MRR, Groundedness %, Refusal Recall, and Latency:
```powershell
python Code\evaluate.py
```

### Step 7: Run Automated Unit Tests
Runs the automated test suite verifying chunking, citation validation, refusal gates, and comparison rules:
```powershell
pytest Code\test_pipeline.py -v
```
